# 任务数据结构与排期算法

## 任务对象

`data/tasks.json` 中每条任务的结构：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 稳定标识，默认取 `sha1(班级名\|标题)` 前 10 位；重复采集不会产生重复条目 |
| `title` | string | 是 | 任务/课程名称，取自页面原文 |
| `kind` | enum | 是 | `course` 课程、`live` 直播（含回看）、`exam` 考试、`survey` 问卷、`class_task` 集中培训（线下班级）、`other` |
| `credit_group` | enum | 是 | 学时归属：`网络自学` / `集中培训`。两组**独立考核、不能互相抵扣**；`class_task` 恒为集中培训 |
| `start` | string\|null | 否 | 线下培训的固定开始日 `YYYY-MM-DD`（班级详情接口），网课为 `null` |
| `place` | string | 否 | 线下培训地点（班级详情 `trainPlace`），网课为空 |
| `required` | bool | 否 | 必修为 `true`；页面只写"选修"时置 `false` |
| `deadline` | string\|null | 否 | `YYYY-MM-DD`。读不到就留 `null`，不要猜 |
| `hours` | float | 否 | 学时。`0` 表示平台未标注 |
| `progress` | int | 否 | 0-100。写成 `45`、`45%`、`已完成` 都能被解析 |
| `status` | enum | 是 | `todo` / `doing` / `done`，状态机见下 |
| `class_name` | string | 否 | 所属培训班，用于拼接稳定 ID |
| `url` | string | 否 | 任务详情页绝对地址 |
| `platform_status` | string | 否 | 平台原文状态，如"学习中""已通过""待考试" |
| `notes` | string | 否 | 人工备注，导入时不会被平台数据覆盖 |
| `first_seen` / `last_seen` | string | 自动 | 首次/最近采集时间 |
| `completed_at` | string\|null | 自动 | 标记完成的时间 |

### 状态机

```
todo ──(有进度)──> doing ──(进度到 100 或人工标记)──> done
                     └──(undo)──> doing
done ──(undo)──> doing
```

- 采集到 `progress > 0` 自动置 `doing`，`progress >= 100` 自动置 `done`。
- 人工 `task done` 后，后续采集不会把它退回 `todo`——平台延迟更新时这一点很重要。

### 学时缺失的处理

平台没标学时时 `hours` 记为 `0`，排期按 **0.3 学时** 估算。宁可略高估，也不要让任务在计划里显示为零成本。

## 优先级算法

分数越高越先做。构成如下：

| 维度 | 取值 |
| --- | --- |
| 已逾期 | 880 + min(逾期天数, 10) × 3 |
| 今天截止 | 980 |
| 明天截止 | 920 |
| 2-3 天内 | 800 |
| 4-5 天内 | 650 |
| 6-7 天内 | 560 |
| 8-10 天内 | 430 |
| 11-20 天内 | 270 |
| 20 天以上 | 150 |
| 无截止日期 | 120 |
| 必修 | 按策略：`layered` +800（默认）、`required-first` +10000、`deadline-first` +180 |
| 类型加权 | 考试 +120、直播 +90、班级任务 +60、课程 +40、问卷 +20 |
| 剩余量加权 | +60 × (1 - 进度/100) |
| 紧迫度密度 | +min(学时 ÷ 剩余天数 × 40, 120) |

**为什么逾期分数低于"今天/明天截止"**：逾期已成既成事实，而临期任务还能挽救。若让逾期任务无条件最高，会出现"为了补旧课而错过明天的考试"。逾期任务靠 +3/天 的递增在 10 天后逼近临期档，长期不处理会重新浮到最前。

必修加权已按用户要求强化为**分层加权**，三种策略的完整分数表、冲突样例与在职工作状态档位见 `@//references/planning.md`。本文件只保留基础字段与排期约束。

## 排期规则

`plan` 子命令按分数降序依次把任务填入每日容量：

1. 每日容量按**在职工作状态档位**逐天取：工作日 `weekday_hours`、周末 `weekend_hours`
   （默认 `office` 档 1.0 / 3.0）；窗口 = `--days`（默认 14）。仅当显式传 `--daily-hours`
   时才退化为全窗口统一容量。详见 `@//references/planning.md`。
2. 未到期任务只能在**自己截止日之前**分配；已逾期任务不受此约束，尽快补完。
3. 单个任务跨天时按天切分，同一天同一任务合并成一行。
4. 放不下的部分进入 `overflow`，`cause` 区分两种原因：
   - `截止日前容量不足` — 该做的做不完，属于真正的风险，必须告知用户并给出建议；
   - `超出计划窗口` — 只是窗口太短，延长 `--days` 即可。
5. 输出同时给出 `suggested_daily_hours = 总剩余学时 ÷ 窗口天数`，用于回答"那我每天得学多久"。

## 导入 JSON 格式

```json
{
  "source": "mooc.ctt.cn/个人学习中心",
  "collected_at": "2026-11-04T19:10:00",
  "tasks": [
    {
      "title": "习近平党建思想相关课程",
      "kind": "课程",
      "required": true,
      "deadline": "2026年11月8日",
      "hours": 4,
      "progress": "50%",
      "class_name": "卷烟营销创新能力提升班",
      "platform_status": "学习中",
      "url": "https://mooc.ctt.cn/#/course/detail/xxxx",
      "notes": ""
    }
  ]
}
```

`task import` 的容错范围：接受裸数组或 `{tasks: [...]}`；`kind` 接受中文；`deadline` 接受 `2026-11-08`、`2026/11/8`、`2026.11.8`、`2026年11月8日`、带时间戳；`progress` 接受数字、百分比字符串、"已完成"。
